## Design Context

### Users

FaceRatioOps is primarily used by portfolio reviewers, DevOps engineers, backend engineers, and the project owner during demos. They need to see how an uploaded image flows through a privacy-first inference API, how operational endpoints behave, and what technical geometry output looks like.

### Brand Personality

Privacy-first, technical, restrained. The interface should feel like an operations console for an AI inference service, not a consumer beauty, identity, medical, or cosmetic product.

### Aesthetic Direction

Use a refined light interface with dense but readable operational information, clear upload flow, and visible API status. Avoid marketing-style hero pages, decorative gradients, personality scoring, attractiveness language, demographic framing, or anything that implies judgment about a person.

### Design Principles

- Show the API workflow directly: choose image, preview locally, analyze, inspect technical output.
- Keep privacy boundaries visible without turning them into marketing copy.
- Treat ratios as neutral geometry measurements and quality warnings as technical input conditions.
- Prefer compact, operational controls and status surfaces over decorative cards.
- Make failure states clear, specific, and non-judgmental.
